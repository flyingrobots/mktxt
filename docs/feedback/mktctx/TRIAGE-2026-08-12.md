## Implemented MKTCTX/5 format tranche

The final accepted protocol work was designed and released together as
MKTCTX/5 rather than as unrelated fields. The coherent tranche is epistemic
metadata:

1. **Orthogonal coverage cardinalities.** Preserve MKTCTX/4's separation of
   representation, profile, and coverage while defining normalized requested,
   included, omitted, and unknown repository-total counts.
2. **Structured diagnostics and omission policy.** Distinguish a structurally
   valid packet from selection-policy compliance. Avoid a single overloaded
   `valid` boolean.
3. **Selection-request provenance.** Canonically record the privacy-safe
   normalized request and policy separately from the resulting file set and
   source identities.
4. **Qualified citations.** Keep compact packet-local citations and define
   packet-qualified and full-content-qualified resolution, alias, and collision
   behavior.
5. **Symbol-ID conformance.** Specify symbol ordinals as minimum-three-digit,
   unbounded, packet-local decimals and add greater-than-999 fixtures.

Because these alter the interpreted packet surface, they were released as
MKTCTX/5 with package version 5.0.0. MKTCTX/4 remains available explicitly for
compatibility and retains its original semantics.

The accepted explainer rewrite followed that tranche. It embeds a
production-generated fixture, states the integrity and Git-bundle boundaries
precisely, validates every diagram, and preserves the pre-existing legacy draft.

## Deferred experiments

| Experiment | Reopen condition |
|---|---|
| File roles and derivation hints | A corpus taxonomy, authoritative derivation provenance, and retrieval improvement |
| Human-facing summary | Cold-open tests show benefit beyond the index and role metadata exists |
| Adaptive or streaming chunks | Giant-line, memory, latency, or citation measurements expose a real failure |
| Unsupported-language outline fallbacks | A language census and gold range tests justify analyzer work |
| Symbol-aware boundaries | Fixed versus snapped versus symbol-primary retrieval evaluation |
| Detached signatures | A concrete attestation claim, trust root, and offline-verification workflow |
| Per-chunk digests | Independent partial retrieval, caching, or retransmission actually exists |
| Task or run receipts | A defensible evidence model plus privacy and redaction policy |

Deferred means “not yet,” not implicit approval. Each item remains independently
reopenable when its recorded evidence trigger exists.

## Rejected product directions

1. **A custom mutation protocol.** `mktxt` packages read context. Unified diffs,
   exact source preconditions, and filesystem tools already carry mutations
   without making this project an authorization or patch-application system.
2. **Core compression, external body references, and delta transport.** Standard
   compression, Git, and content-addressed stores already solve those transport
   problems. Required external state would weaken MKTCTX's standalone,
   model-readable property.
3. **A second capability-profile version.** Protocol magic, named projection
   profiles, section statuses, and per-file projections already state the
   testable guarantees.
4. **Causal parent packet chains.** This duplicates Git/CAS history and makes
   deletion, omission, parent retention, and garbage collection harder.
5. **A second `C...` content-ID syntax.** Full source SHA-256 already provides
   content identity independently of path-derived file IDs; Git records provide
   rename evidence.
6. **In-band random-access offsets.** Consumers can build an offset map during
   strict parsing. Wire offsets add entropy and serialization coupling without
   a measured seek bottleneck.

Rejected means the idea does not belong in the current product design. An item
can be reconsidered only if new evidence defeats the recorded rationale or the
product boundary explicitly changes.

## Superseded duplicates

- Gemini's general delimiter-collision concern is covered by MKTCTX/4's
  authoritative byte framing, normative grammar, and local model-visible data
  boundary.
- A separate lossy companion protocol is covered by review and structure
  profiles with explicit signatures, outline, and reference projections.
- Symbol-aware RAG chunks collapse into the narrower deferred boundary-quality
  experiment; retrieval identities should wait for an actual retrieval system.
- Conversation delta packets collapse into the rejected causal-chain and
  differential-transport direction.

## Governing principle

MKTCTX remains a standalone, verifiable, self-describing source-context packet.
Its core should improve truthfulness about selection, fidelity, provenance, and
citations. Retrieval systems, attestations, transports, and agent-run receipts
may consume or bind packets, but they should not be pulled into the core format
before a real workflow proves that they belong there.
